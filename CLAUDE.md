# LineHunter project notes

## Folder structure
- Root: the HTML pages, `CLAUDE.md`, `netlify.toml`, `robots.txt`, `.gitignore`, `.env.example`, `netlify/` (the API proxy function and the password-gate edge function).
- `css/styles.css` — the whole design. `assets/img/` — logo files, favicons and screenshots. `dev/` — test pages (paths there start with `../`).
- `js/core/` — shared logic every page needs (`api.js` theme/palette helpers, `stats.js` API requests + hit-rate math, the unused local `config.js`). `js/data/` — static data (`teams.js`). `js/pages/` — one script per page (`app.js` = schedule, `game.js`, `player.js`, `standings.js`). `js/components/` — reusable parts and page cards (`nav.js`, charts, drawer, Hit List, Top Hit Rates, share, shelf, quick look, matchup/injury/compare cards...).
- Script loading order on every page is unchanged by the folder move; only the paths differ.

## Script usage
- `js/components/nav.js` — shared top navigation and drawer, plus the responsible gaming footer (`.lh-footer`), injected on every page that has `#site-nav`
- `js/pages/app.js` — runs on `schedule.html` to load the current NBA schedule and pager. Game cards (Oct 2026) are Swiss `.lh-gc` cards like the game page header: tip time, abbreviations with a team-colored underline (`matchupColors`, clash rule; no tints or city watermarks any more), city + record (`fetchStandings` from `matchupInfo.js`, `overall`), the spread / total line (one `/nba/v2/odds?game_ids[]=…` request for the day, `pickOddsRow`; lines-only), the Quick look collapse (injuries, top prop, "Model picks": the spread and total picks with their strength from `gameModelFor` in `gameBreakdown.js`) and a QUICK LOOK | VIEW PROPS › footer. Phones: the card peeking in is faded (`.is-peek`, `markPeekingCards`), and on a first visit the row nudges left and back once (`.is-hinting`, localStorage `lh-swipe-hint`; none with reduced motion). The day's games are a scroll-snap carousel (`#games-list`, `.lh-games-track`): 3 cards per page on desktop, 2 on tablets, 1 on phones, with ‹ › buttons and a "1–3 of 8" counter (`updateGamesCarousel`), so a big slate doesn't push the tool tiles down. It calls `showTodayForDay(day)` then `showTopHitRatesForDay(day, games)` for the picked day
- `js/data/teams.js` — `TEAM_INFO[abbreviation] = { arena, city, coach, colors: { primary, secondary } }` for all 30 teams, plus the team-color helpers used site-wide (loaded on game, schedule, player and home pages): `matchupColors(away, home)` (each team's color made visible on the dark background — nearly-black primaries fall back to the secondary or a lighter tint, `ensureContrast`; **color clash rule**: if the two main colors are closer than 80 RGB steps the AWAY team uses its secondary), `applyMatchupColors(card, away, home)` (adds `.lh-team-card` + `--away` / `--home`: a 15% tint per side split by a thin diagonal slash and a soft edge glow, on the game page header and every schedule game card), `teamBadgeHtml` / `teamBadgeForMatchup` (the team abbreviation next to player names, styled as plain display-font letters in the team color blended 50/50 with the muted text color plus a 2px team-color underline — no pill or fill; shown in the props table, drawer, Hit List / Streaks cards, Top Hit Rates and the player header), and `teamAvatarStyle` (team-colored initials circles with white or dark text, whichever passes 4.5:1 — With / Without chips). Colors come from teamcolorcodes.com; the Utah Jazz hex values are approximations (see the file header). Team abbreviations on the matchup cards keep their own neutral colors. City watermarks: every team has a `watermark` word in `TEAM_INFO` (e.g. PHI "PHILLY", CHI "CHI-TOWN"; `city` there is the arena's city). `addCityWatermarks` (called by `applyMatchupColors`) draws each team's word vertically along its own outer edge of the game page header and every Schedule game card (away = left edge reading bottom to top, home = right edge reading top to bottom, centered), in the matchup color (clash rule included) at 16% with a soft top/bottom fade, Inter Tight 800 (Comico was removed in the Swiss restyle), behind the content, `aria-hidden`, click-through. The font is fitted (ResizeObserver) so the whole word fits the card height (max 40px), and the card keeps 3.25rem of side padding. The word is always fully visible and still; while the card is on screen (IntersectionObserver adds `.is-shining`, so a new carousel set starts a fresh sweep) a soft band of light sweeps along each word, CSS only (`.lh-city-text::before`, the `.lh-shine` technique along the vertical word): 2s sweep then a 3s rest (5s cycle), the home word 0.3s after the away word, band = a lighter tint of the team color on dark (`--lh-city-shine-keep: 45%`) and the team color itself, a bit stronger, on light; reduced motion shows the still word (checked Oct 2026; the file header lists what changed recently). `js/components/matchupInfo.js` — the "Matchup Info" card beside the game header on `game.html` (header `col-lg-7`, info `col-lg-5`, both `h-100`): arena · city, coach, (last 5 W/L dots + record now sit under each team's name in the header card: `#formAway` / `#formHome`), home team's home record vs away team's road record (from `/v1/standings`, last season with a "Last season" tag when the season has no games), rest days with a B2B badge, and the last meeting (finished game between the two teams; last season if none this season). Team games are fetched per team with `team_ids[]` and filtered; standings and games are cached in sessionStorage (`lh-standings:…` 1 hour, `lh-team-games:…` 10 minutes)
- `js/components/teamCompare.js` — the "Matchup Details" card on `game.html` (the team comparison): a full-width card, always visible, directly below the props / stats card (page order: header + Matchup Info row, Player Props / Player Stats card, Matchup Details). Its data downloads when the card scrolls into view (IntersectionObserver, 200px early); until then it shows loading rows. Butterfly rows for PPG, Opp PPG, Pace, Off/Def/Net Rtg, RPG, APG, 3PM, FG%, 3P%, TOV (two columns of 6 on wide screens, one on phones): away value + rank chip, bar growing left, label, bar growing right, rank chip + home value. Bars are scaled to the league's worst → best (flipped for lower-is-better stats); the better team is the over color, the other the under color, Pace gray. Ranks are computed from all 30 teams (#1 = best, lowest for Opp PPG / TOV / Def Rtg). Data: `/nba/v1/team_season_averages/general?type=base|opponent|advanced&per_page=100` (this season, else last season labeled "Last season"), cached in sessionStorage (`lh-team-compare:…`, 1 hour)
- `js/components/gameBreakdown.js` — the "Game Breakdown" card on `game.html` (kicker "Spread & total") and the model line in the Today Quick look (`gameModelFor(game)`). Projected score: possessions = away pace × home pace ÷ league pace; each team's points = possessions × (its Off Rtg × the other's Def Rtg ÷ league rating) ÷ 100; then home court (`GB_CONFIG.homeEdge` 0.9 each way = 1.8 points of margin), back-to-back (a team that played yesterday loses `b2bPct` 1.4%, from `/v1/games` for the day before) and injuries (each player listed Out / Doubtful at full weight, Questionable / Day-To-Day at half, 10+ minutes a game: his points a game × (1 − `injury.keep` 0.88) from `season_averages/general?type=base` (this season once he has 5 games, else last season); a player who has sat out this season's games only counts for the last-season part of the ratings blend). Ratings = this season's gap to the league blended with last season's (weight games ÷ (games + 10)). Teaser: scoreboard (leader in full ink), the **spread pick** and **total pick** (`gbPicks`: always a side vs the book, strength from the gap: Slight < 1.5, Moderate 1.5–3, Strong > 3; Hit / Missed / Push tags once Final; under each pick a Book · DK | Model | Gap row, the spread written for the picked team in +/− line notation, so the model winning by 7 reads "NYK −7.0"), the injuries line, the strength note ("…not guaranteed"); research mode shows the model's margin and total instead. "Show breakdown details": possessions, the lines-only model vs book total number line, the "Score build-up" table (each step's running score for both teams + total, with deltas), "Who is missing" and the ratings note. Book = the Sportsbook filter's, else DraftKings, else the first posting a total. `window.lhGameBreakdown` holds the numbers (incl. `picks`) for console testing.

## Hunt Score engine (used by the Today page's Top 5 Hunts card and hunt-score.html)
- `netlify/functions/hunt.js`, reached at `/api/hunt?date=YYYY-MM-DD` (default today, America/New_York; redirect in `netlify.toml`; covered by the password gate's `/*`). Scores the OVER and UNDER of every PTS / REB / AST / 3PM / PRA prop on games that have not started (future dates and started games return an empty list) with a **simulation**: per player + prop it projects a per-minute rate and minutes (last season's rate and minutes from one `/nba/v1/season_averages/general` request, its game logs only from Feb 1 on, for speed; this season recency-weighted, a game's weight halves every 5 games, blended with a prior that counts as 5 games: last season while the player has under 20 games this season, else this season's flat average; a player traded during last season gets last season's games with his CURRENT team only as the prior once he has 10 (`loadTeamChanges`: one `/v1/stats` page per 5 of those players spots a second team, then the traded ones' full season; `CONFIG.sim.teamPrior`; each prop carries `teamPrior` = { team, games, other }, and the "why" says "last season with OKC"); only logs from before the slate date), then the **role** step (tonight's lineup: teammates listed Out / Doubtful who usually play 15+ minutes AND have played for the team this season are missing (out all season = already in the numbers); the player's past regular-season games on this team where at least half of those minutes were also missing are his role games, minus his own short nights (under 80% of his usual minutes: injury, a limit, a blowout, a rest night; a late-season game where he played big minutes still counts); 3+ needed; a role game where other rotation teammates (the slate's players with 15+ usual minutes) also sat counts half with 1 more out and not at all with 2+ (`extraKeep`, `buildRotation`: late-season tank games and games without the star are not tonight's lineup: Fears' April 36 / 36 / 40); newest count most, last season's (from Feb 1) half; how much the missing teammates matter is `importance` (their production of the prop's stat per game, 0 at 35% of a per-stat reference up to 1 at the reference: PTS 14, REB 6, AST 4, 3PM 2, PRA 22; under 10% there is no Role step; Santos 7.2 points = about a fifth, Banchero = full) and multiplies both weights below (`CONFIG.sim.role.mode`: "old" = no importance, "importance" = default, "lift" = also the lift over his non-role games; on 730 Role-affected sides of Oct 28-30 the three scored the same, Brier 0.2518 / 0.2520 / 0.2519); their minutes replace the form minutes in proportion n / (n + 2) (n / (n + 0.5), and 2 role games are enough instead of 3, when any missing teammate shares a listed position letter G / F / C with him: `samePos`, Sengun "F-C" out and Capela "C") and their per-minute output the form rate in proportion n / (n + 6); `CONFIG.sim.role`, `loadMissing` + `roleInfo`; factor `role` with `out`, `games`, `from`, `minutes`; the Hunt Score page shows "Williams, Holmgren out · 20.1 → 24.6 min"), multiplies by opponent (stat allowed vs league, half the gap), zone matchup (PTS / 3PM / PRA only: the player's FGA per game by zone from `season_averages/shooting?type=by_zone` (this season once he has 10 games, else last season) x (the FG% the opponent allows there − the league's, from `team_season_averages/shooting?type=by_zone_opponent`, corners combined) x 2 or 3 points (3PM: extra makes), as a share of his usual output, half of it, capped ±6%: `CONFIG.sim.zone`; factor `zone` with `extra` = points (or threes) vs an average defense and `zone` = the biggest gap's words, "the rim" etc.; skipped under 4 FGA a game) and pace (tonight's expected pace vs the player's usual, half the gap) and back-to-back (x0.97), pulls the projected mean toward the book's line (20%, up to 50% when the player has few games this season: `CONFIG.sim.market`; a big disagreement means the book likely knows something: past a 25% gap (over the line, or the stat's `gapFloor` for tiny lines: PTS 8, REB 4, AST 3, 3PM 2, PRA 12) the pull grows to 70% at 50% and the rate uncertainty widens by up to 0.1; `market` detail has `gap` %, the spread step `bookGap`, and the why sentence names it), then runs 2,000 seeded Monte Carlo games (minutes noise = the player's own spread, x1.5 for a game-time decision; rate noise = 0.05 + 0.3/sqrt(games), wider when the last 3 games disagree with the projection; game-to-game noise = negative binomial k fitted from the logs). Score = the chance itself (`50 + (chance - 0.5) * 100`: 65% -> 65), clamped 0-100. The score is built in steps from a **season baseline** (season-level rate and minutes, average opponent, normal spread; `base`), and each factor's `points` = how much its step moved the score, so `base` + factors = the score before rounding: `minutes` (`now`, `base`), `form` (`last` = last-3 average, `games`), `role` (`out`, `games`, `from`, `minutes`), `opponent` (`rank`, `of`, `perGame`), `zone` (`extra`, `zone`, `gap`), `pace` (`rank`, `of`, `pace`), `b2b`, `market` = "Book line" (`line`, `sim` = the projection before it, `weight` %), `spread` = "Uncertainty" (`games`, `lastSeason`, `disagree`, `gtd`). Each prop also has `chance` (% for that side, pushes left out), `odds` + `book` (the side's price: the picked book's, else the first book pricing it; `loadLines` `prices`), `fair` (the book's fair chance with its cut taken out: both sides' implied chances scaled to 100%, or one side's minus 2.25%; `fairChances`) and `edge` (chance − fair, in points) and `projection` (`mean`, `p10`, `p90`). All weights are in `CONFIG` (`CONFIG.sim`) at the top. Props with under 5 games are skipped, and so is any side no book prices at that exact line (`loadLines` keeps only over_under markets with a price, DraftKings first; `priced.over / .under`), so every listed prop and top hunt has odds. Three template sentences per prop (`why`, every number real): 1) L10 record + average (+ minutes when they moved 2+) and "The sim projects 5.7 (most games 3 to 9), a 77% chance of going under", 2) the matchup (opponent rank for that stat, middle-of-the-league wording for ranks 9–22, plus pace when top / bottom 5), 3) the biggest risk (the most negative piece, the baseline included: small sample, swinging recent games, game-time decision, back-to-back with the player's own B2B cost, matchup, pace, minutes, form, the line itself) weighed against the biggest plus, or "No real red flags". `topHunts` = best score per player, 65+, not injured, max 5. CDN cache 10 minutes, and a warm function keeps its answer per date 10 minutes (`warmCache`), so the Today card and the Hunt Score page read the same numbers. `dev/hunt-test.html` shows the numbers in a table; `dev/hunt-compare.js` prints old vs new scores for a slate (writes the gitignored `dev/hunt-compare.txt`). `dev/hunt-whatif.js [date] [name] [stat]` (localhost, key from `.env`): old engine (`CONFIG.sim.role.off`) vs now for the top hunts of both (or one prop by name), overs vs unders at 65+, every Role step's games (`CONFIG.debug` puts them in the factor: date, opponent, minutes, stat, who was out, and each prop's `history` = past games over / under its line, and `roleMiss` = teammates out but no Role step: the reason and every game without them, counted or skipped and why), an under-bias check (projection vs line before and after the book-line pull, share under the line, per stat, by games this season and for low lines) a top 10 by edge (best edge per player, chance 55%+, not injured, with the over / under split and the average edge per side) and a calibration check (the sim's and the baseline's under chance vs how often he actually went under that line, overall, per stat, low lines and by sim bucket) (gitignored `dev/hunt-whatif.txt`). `dev/hunt-grade.js [date]` replays main's old engine and this branch's engine on a saved snapshot (`dev/hunt-replay.js`) and grades every side of the FINAL games against the box scores (hit rate and profit per $100 at the saved price, by score bucket for both engines, by edge / side / stat for the new one, top 5 by score, top 10 by edge, top score per game, and the compared players vs Sam from `dev/hunt-sam.json`; gitignored `dev/hunt-grade.txt`). `dev/hunt-games.js` runs the Game Breakdown model (`js/components/gameBreakdown.js`, unchanged, in a Node vm) for `dev/hunt-snapshot.js`, which now also saves each game's book lines (`gameOdds`) and our model's call (`model`) before tip-off; `node dev/hunt-games.js DATE` grades the spread and total picks vs the book and the final scores (the API keeps only in-game lines after a game; gitignored `dev/hunt-games.txt`); `dev/hunt-backup.sh` pushes the snapshots to the `hunt-snapshots` data branch. `dev/hunt-backtest-check.js [date]` (localhost) is step 1 of a backtest: for up to 3 finished games of a date (default yesterday) it shows whether `/nba/v2/odds/player_props` still returns lines, the books and market types, one raw prop, every timestamp field vs tip-off, and a few lines next to the final stat (gitignored `dev/hunt-backtest-check.txt`). Sentences name the player by last name. `injured` = Out / Doubtful / Questionable / Day-To-Day; `gtd` = the Questionable / Day-To-Day ones (shown with a GTD tag, never in `topHunts`).

## Projection backtest and the "teammates back" step (branch only)
- `dev/hunt-proj-backtest.js [--from --to --variants norole,old,importance,lift,back]` replays past slates from box scores only (no book lines): synthetic lines (L10 rounded), "Out" = regulars who did not play, market pull off, then compares `projection.mean` with the real stat (MAE, bias, Brier; gitignored `dev/hunt-proj-backtest.txt`). Oct 24 - Nov 4 (6,130 player-stats): naive L10 MAE 3.154, no Role 3.032, Role old 3.012, importance 3.004, lift 3.009; on the 1,515 Role-affected ones 3.200 / 3.028 / 2.948 / 2.916 / 2.936, so Role helps and importance is best.
- `CONFIG.sim.back` + `backInfo` ("Teammates back" step, after Role, only when no Role step): healthy rotation players who missed 2+ of the player's games lead his form toward his full-lineup games. Backtest: no gain (MAE 3.006 vs 3.004), so it ships OFF (`off: true`); `back` variant turns it on.

- `CONFIG.sim.position` + `loadPositionDefense` / `positionInfo` ("Position matchup" step, after Matchup): one paged `/v1/stats` of the season's box scores; for each player-game (10+ min) his stat vs his own earlier average, summed per opponent and position letter (G/F/C, first listed); multiplier = (position ratio / the team's overall ratio), half of it, shrunk by n/(n+40), capped +/-5%. Backtest (same 6,130): MAE 3.007 vs 3.004 without it, Brier 0.2262 vs 0.2261, so no gain this early in the season; ships OFF (`off: true`), the `pos` variant turns it on. Worth re-running once teams have 30+ games.

- Step-strength tuning (same 6,130 projections, one setting changed at a time, base MAE 3.004 / Brier 0.2261): recency half-life 3 / 8 / 15 / flat 3.007 / 3.004 / 3.004 / 3.005; prior weight 2 / 10 games 2.998 (Brier 0.2288, worse) / 3.045; opponent strength 0 / 0.25 / 1.0 3.007 (Brier 0.2271) / 3.003 / 3.015; pace 0 / 1.0 3.004 / 3.005; back-to-back x1.0 / x0.94 3.005 / 3.004; zone 0 / 1.0 3.003 / 3.007. Everything is within 0.01 of the current settings, so none were changed (the opponent step does help the Brier score).

- `dev/hunt-under-check.js` (part of the 10 am report): over all saved final nights, how often lines go under (per night, game-clustered error), by stat x line size, and whether the engine's under chance / edge predicts the result (Brier vs the base rate). Nov 5-7 result (2,361 lines): 53.3% under (2.4 sigma over 50%, 0.7 over break-even), the engine's under chance did not beat the constant base rate (Brier 0.2527 vs 0.2489) and higher under edge won LESS (edge 15+: 44.1%), so do not rank by edge.

- `dev/hunt-calibrate.js [--variants base,mk15,mk2,mk25,cv3,cv6,mk2cv3]` (gitignored `dev/hunt-calibrate.txt`): replays every saved night on its saved lines under settings variants and grades EVERY scored side against the box scores (Brier / log loss, calibration table, 65+ picks, edge 10+, top 10 per night), then fits a post-hoc shrink of the chances leave-one-night-out. Nov 8 run (6 nights, 4,630 sides): the base engine's Brier is 0.2525, WORSE than always saying 50% (0.2500); its 65+ picks said 67.5% and won 57.1% (196 picks); edge 10+ won 48.0%. A stronger book-line pull helps calibration (market weights x1.5 / x2 / x2.5: Brier 0.2511 / 0.2502 / 0.2498) but leaves almost no 65+ picks (99 / 30 / 9) because the engine then mostly agrees with the book; wider rate uncertainty (cv3 / cv6) does nothing (0.2524). Shrinking the chances toward 50% keeping k = 0.30 of the gap gives held-out Brier 0.2496; toward each side's base rate (over 46.9%, under 53.1%) k = 0.15 gives 0.2492, about the same as the constant base rate with no model (0.2490). So on these nights the engine's probabilities carry little information beyond the base rate; its ranking value is still unproven. Nothing changed in the engine; a shrink would not change the order of picks, only the shown percentages.

- `dev/hunt-vs-line.js` (gitignored `dev/hunt-vs-line.txt`): is the model a better guess of the final stat than the book's line? Replays the saved nights with the book-line pull OFF and compares the line, the model alone and the engine's normal projection with the real box scores. Nov 8 run (6 nights, 2,315 player-stats): average miss (MAE) line 3.282, model alone 3.449, engine now (20% pull) 3.349; RMSE 4.841 / 5.092 / 4.940; the model alone runs high (bias +0.33 vs +0.12 for the line; PTS +0.71, PRA +0.81). Blend actual - line = a + b x (model - line): b = -0.07 overall (PTS 0.06, REB 0.03, PRA -0.20, AST 0.46, 3PM 0.53); fitted on the other nights, the blend does not beat the line on the held-out night (RMSE 4.849 vs 4.841). Direction: when the model says over it went over only 43-49% (base rate 46.9%); when it says under it went under 50-56% for small gaps and 60.5% (185 sides) for gaps over 20% (base 53.1%). So on these nights the line is the better predictor; the model's only visible signal is AST / 3PM (small samples) and big-gap unders.

## H2H (head-to-head) chip
- `js/core/h2h.js` (loaded after `stats.js` on `player.html`, `game.html`, `schedule.html`): `loadH2H(teamId, opponentId)` = the team's games for this season + the 4 before (one `/v1/games?team_ids[]=&seasons[]=` request per season, regular season + playoffs, kept when Final and against the opponent), then ONE paged `/v1/stats?game_ids[]=…` for all of them (every player on both teams), memoized per team pair. `h2hLogsFor`, `splitGames`, `h2hSplitOptions`, `h2hNoteHtml`, `loadH2HForGame(gameId)` are shared. `loadH2H` (team pair) is used by the Matchup Analysis card and the Analyzer. The H2H chip (player page and both drawers) uses `loadPlayerH2H(playerId, opponentId)` instead: that player's own lines against the opponent over the same 5 seasons, whichever team he was on (one `/v1/stats?player_ids[]=&seasons[]=` request per season, memoized; drawers go through `loadPlayerH2HForGame(playerId, gameId, oppAbbr)` / `h2hTeamIdIn`), so players who changed teams still get their games. `hunt.html` loads `h2h.js` too (its drawer needs it). The proxy caches `/v1/stats?game_ids[]` for 24 h when every game was Final before today.
- The chip group All / Home / Away / **H2H** is on the player page (`#playerSplits`) and in both drawers (`#playerDrawerSplits`, game page `js/components/player-drawer.js` and schedule `js/components/schedule-drawer.js`). H2H replaces Home / Away, loads on first pick, L5 / L10 / L20 count games vs that team and Season = every H2H game in the range. ## Request savings (schedule page)
- `bdlGet` (`js/core/stats.js`) keeps answers in memory per full URL with expiry that mirrors the proxy (`bdlMemoryTtl`: odds 2 min, games / box scores 30 s, everything else 10 min, past seasons and past days never), shares in-flight requests, and hands each caller its own copy (`structuredClone`).
- `loadPlayerGameLogs(ids, n, { recent: true })` (Top Hit Rates only): this season's last 90 days and last season from January 1, 10 players per request. Game page, player page and drawers still load full seasons. Season-level numbers (Hot Players / Streaks / Brick City / BBQ season averages and FG%) come from `loadSeasonAverages` (`/nba/v1/season_averages/general`, this season once a player has 10+ games, else last season, labeled "last season" via `slate.fan[i].seasonLabel`). Hit List streaks and matchup counts only reach back to January.
