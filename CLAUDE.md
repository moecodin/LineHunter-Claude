# LineHunter project notes

## Folder structure
- Root: the HTML pages, `CLAUDE.md`, `netlify.toml`, `robots.txt`, `.gitignore`, `.env.example`, `netlify/` (the API proxy function and the password-gate edge function).
- `css/styles.css` — the whole design. `assets/img/` — logo files, favicons and screenshots. `dev/` — test pages (paths there start with `../`).
- `js/core/` — shared logic every page needs (`api.js` theme/palette helpers, `stats.js` API requests + hit-rate math, the unused local `config.js`). `js/data/` — static data (`teams.js`). `js/pages/` — one script per page (`app.js` = schedule, `game.js`, `player.js`, `standings.js`). `js/components/` — reusable parts and page cards (`nav.js`, charts, drawer, Hit List, Top Hit Rates, share, shelf, quick look, matchup/injury/compare cards...).
- Script loading order on every page is unchanged by the folder move; only the paths differ.

## Pages
- `index.html` — dedicated homepage previewing LineHunter tools and value proposition, plus a live Top Hit Rates card
- `schedule.html` — today's games list and date pager; keeps the schedule view separate from the homepage
- `game.html` — matchup page for a selected game with player props
- `standings.html` — NBA standings (Conference / Division views)
- `hit-list.html` — "Hit List — coming soon" placeholder (the schedule page's Hit List carousel card links here)
- `nfl.html` — NFL "coming soon" page (same layout, navbar, footer, theme toggle and styles; Comico headline "Kickoff soon", a short list of what's coming, a "Back to NBA" button; football emoji, no logos). `<body class="lh-nfl-page">` hides the research mode switch and the NBA player search there
- `props.html` — placeholder player props page
- `player.html` — player page (`player.html?id=PLAYER_ID&prop=pts`): header with injury badge (popover) and next game, season averages strip, prop chart with tabs / L5–Season / All–Home–Away / alt line, then a full-width game log table that follows the filters (the 10 most recent games show first; a "Show all games (N)" / "Show fewer" button collapses the rest via a second `<tbody id="gameLogMore">`), a row of three equal cards (With / Without, Opportunity, Role with its Minutes / Usage % toggle; all follow the same games and filters as the main chart), and a row of two season-level cards (Shot Chart, Zone Matchup). Tablets and phones stack them in that order (FG, 3P, FT made/attempted after MIN, USG% at the end, Date and Opp columns sticky while scrolling sideways)
- `dev/hitrate-test.html` — console-only test page for the hit-rate functions

## Hunt Score engine (no UI on any page yet; nothing calls /api/hunt)
- `netlify/functions/hunt.js`, reached at `/api/hunt?date=YYYY-MM-DD` (default today, America/New_York; redirect in `netlify.toml`; covered by the password gate's `/*`). Scores the OVER and UNDER of every PTS / REB / AST / 3PM / PRA prop on games that have not started (future dates and started games return an empty list): 50 + L10 hit rate `(rate-0.5)*40` + season hit rate `(rate-0.5)*20` (last season when under 10 games this season) + line vs L10 average (% gap * 0.5, capped +-8) + opponent rank (from `team_season_averages/general?type=opponent`, +8 best to -8 worst) + minutes trend `(L5 - season minutes)*1.5` (capped +-6) + back-to-back -4, clamped 0-100. All weights are in the `CONFIG` object at the top. Props with under 5 games are skipped; Out / Doubtful / Questionable players are flagged `injured`. Three template sentences per prop (`why`), `topHunts` = best score per player, 65+, not injured, max 5. CDN cache 10 minutes. `dev/hunt-test.html` shows the numbers in a table. Sentences name the player by last name. `injured` = Out / Doubtful / Questionable / Day-To-Day; `gtd` = the Questionable / Day-To-Day ones (shown with a GTD tag, never in `topHunts`).

## My Hunts step 2 (prop toolbar, best odds, compact phone rows, floating pill)
- `js/data/odds.js` (`lhOdds`): pages hand it every sportsbook's raw props (`ingest`: game page, player page, Top Hit Rates build); `getOdds(playerId, propType, line, side)` -> `[{ book: "DK", vendor, odds }]` best payout first, exact line + side, `[]` when no book posts it. over_under markets give both sides; milestone markets ("6+ assists") are converted to Over-only alt lines (whole N → Over N−0.5, a .5 milestone → Over at that exact line); Under on alt lines is empty (the side stays selected, odds hidden, Add disabled, no note). Book labels: `lhHunts.bookLabel()` in `js/core/hunts.js` (DK FD MGM CZR BR 365 FAN ESPN HR BALLY PARX ...). Vendors seen in the data (Oct 2026): draftkings, fanduel, betrivers, caesars, betparx, ballybet, fanatics. Each vendor posts one over_under line per player + prop, so odds exist only for lines a book actually posts.
- `js/components/prop-toolbar.js` (`createPropToolbar`): charcoal panel at the top of the player drawer and the player page (lines mode, `lines-only`; the page's existing stat tabs are moved into it and go back in research mode). Stepper in 1-point steps (keeps the chosen Over / Under; the side resets when the drawer closes or the player / prop changes), Over | Under (selected Over teal, Under coral), up to 3 odds boxes + "+N" (best outlined, odds teal), "ADD TO MY HUNTS" / "IN MY HUNTS" (teal) with `isAlt` = line differs from the chart's starting line. Nothing picked: hint "PICK OVER OR UNDER"; no book posts the line + side: no odds and no Add. The chart is built with `externalLine: true` (its own alt − / + hidden, `setActiveLine()` / `mainLine()` used by the toolbar; the research milestone control stays). `?side=over|under` on `game.html` / `player.html` preselects a side (Top Hit Rates and Hit List links add it).
- Top Hit Rates tickets carry `bestOdds` per side (cache invalidated if missing). Desktop: odds chip before a labeled "+ ADD" button. Under 768px: `.lh-mrow` compact tickets (3px teal / coral edge, dashed stub with notches: odds chip, hit rate, window), no + button, tap opens the drawer on that prop and side; header drops the description, controls on one row, Sort icon only. - Floating pill `#lhHuntsPill` (`js/components/my-hunts.js`): MY HUNTS | dashed divider | count + chevron, bottom right; phones only once the slip has a leg, above the tab bar; hidden while the drawer is open (`body.lh-hunts-open`); opens the drawer. ## Top Hit Rates: Sportsbook filter and player search
- Sportsbook: a 4th pill (desktop; phones get a "Sportsbook" field inside the Filter sheet) listing "Best odds" + the vendors in the odds data (`lhOdds.vendors()`, names from `lhOdds.vendorName`). The choice is `lhOdds.getBook()` / `setBook()` (localStorage `lh-odds-book`, event `lh-book-change`), shown as a removable "Book: FanDuel" chip. With a book chosen each row moves to that book's own line (`lhOdds.bookLine`: over_under line, else decimal milestone, else the row is hidden; whole-number ladders are alt lines only), the hit rate is recomputed from the games in memory (`topStatsAtLine`), the stronger side is picked as before, only that book's odds show (no "+N"), and Add is disabled where the book has no price. `lhOdds.getOdds()` defaults to the chosen book, so the drawers, the player page and the toolbar follow it; drawers / player page start on `lhOdds.startLine()`. The game page's table columns still show the consensus line.
- Limit: rows exist only for player + prop pairs that have an over_under line from some book (`pickOneLinePerPlayer`); a pair only a milestone book posts (about 4 of 183 on 10/20) has no row, so it can't appear under any book.
- Search: `#topHitRatesSearch` under the pills; every typed word must start some word of the name (accents / case ignored, `topNameMatches`); filters live, combined with the tabs, window, Filter, Sort and book; X button, Esc, "No players match".

## Research mode
- A visitor-level switch (`localStorage` key `lh-mode` = `"research"`; lines mode is the default and is unchanged). ## Themes (light / dark)
- Every page's `<head>` has an inline script that sets `data-bs-theme` ("light" or "dark") on `<html>` from localStorage `lh-theme` before anything renders (default dark, wrapped in try/catch). `js/components/nav.js` owns the toggle (`setTheme`, `isLightTheme`, the `lh-theme-change` event): a sun / moon button in the navbar on desktop and a "Light mode" switch in the phone "More" sheet.
- `css/styles.css` has two token blocks with the SAME names: `:root, [data-bs-theme="dark"]` (the original values) and `[data-bs-theme="light"]` (off-white `#faf9fd` page, white cards with thin light-purple borders, near-black `--lh-strong` headings, deeper purple accent, darker teal / coral, amber status colors with no yellow text). Beyond the original tokens: `--lh-strong` (white / near-black text), `--lh-ink-rgb` (faint white tints / dark tints), `--lh-bg-rgb`, `--lh-surface-rgb`, `--lh-deep-rgb`, `--lh-hero-rgb`, `--lh-line-rgb`, `--lh-accent-2` (accent gradient end), `--lh-out` / `--lh-dtd` / `--lh-q` / `--lh-warn` (+ `-rgb` tints) for status colors, `--lh-over-rgb` / `--lh-under-rgb` / `--lh-push-rgb`, and strength multipliers `--lh-shadow-k`, `--lh-glow-k`, `--lh-tint-k` (1 in dark, small in light). Write new CSS with these tokens, not hex / rgb. The logo letters follow `--lh-logo-ink`; mask gradients keep `#000` (they are masks, not colors); white text on colored fills (primary buttons, diet segments, "NEW" badge) stays white.
- JavaScript is theme-aware too (nothing is hardcoded to dark any more): `js/core/api.js` has `isLightTheme()`, and `cssVar(name, root)`, plus the display palettes `TEAM_COLORS` (dark) / `TEAM_COLORS_LIGHT` and `getNeutralTeamIndex` (the matchup-card abbreviations are classes `.lh-abbr` + `.lh-abbr-0..9`, one gray set per theme, no inline styles). The charts (`js/components/propChart.js` `chartColors()`, `js/components/roleChart.js` `palette()`) read every color from CSS variables each time they draw and redraw on `lh-theme-change`. `js/data/teams.js` reads the page background from `--lh-bg` (`pageBackground()`): `ensureContrast` tints toward white on a dark page and shades toward black on a light one, `teamBaseColor` falls back to the secondary for team colors that vanish on the page (Nets, Nuggets on dark; Spurs silver on light), `readableTextOn` tries white first on dark and dark first on light, and `refreshTeamColors(root)` redoes matchup cards, badges (`data-team`) and initials circles (`data-avatar-team`) on theme change. Team tint / city watermark opacity per theme are `--lh-team-tint` (0.15 dark, 0.20 light) and `--lh-city-alpha` (0.16 / 0.26). Shared images follow the page's theme: the off-screen share box has no theme of its own (a light page makes a light picture), the html2canvas background is read from `--lh-bg`, and `chart.toImage()` snapshots the chart as it is drawn.
